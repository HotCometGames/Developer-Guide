# Team Formation & Roles

> Finding the right people, assigning responsibilities, and staying coordinated when the clock is ticking.

> **Related:** [Choosing an Idea](choosing-an-idea.md) | [Time Management](time-management.md)

---

## Solo vs Team

| | Solo | Team |
|--|------|------|
| **Alignment** | No coordination overhead | Need to communicate |
| **Scope** | Must do everything yourself | Can divide and conquer |
| **Resilience** | Sick or stuck = project stalls | Someone else can pick up |
| **Learning** | You touch every part of the stack | You go deeper in your area |
| **Fun** | Lonelier | Shared victory |
| **Best for** | Experienced participants, tight jams | First-timers, complex projects |

> **Recommendation:** If you're a first-timer, join a team. You'll learn faster and have more fun. Go solo when you know what you're doing and want full creative control.

## Forming a Team

### At the Event

| Method | How |
|--------|-----|
| **Pre-event** | Use Discord, Slack, or social media to find teammates before the event |
| **Kickoff** | Most events have a team formation session — pitch yourself and your skills |
| **Friends** | Bring people you already work well with |
| **Random** | Join a team looking for your skill set |

### What to Look For

| Quality | Why It Matters |
|---------|---------------|
| **Reliable** | Shows up and delivers — the most important trait |
| **Complementary skills** | Covers what you can't do (design, audio, backend) |
| **Good communicator** | Clear about progress and blockers |
| **Similar ambition** | Wants the same level of polish/scope |

> **Tip:** A team of 3-4 people who have worked together before is ideal. The coordination cost is low, and trust is already established.

## Team Size

| Size | Hackathon | Game Jam |
|------|-----------|----------|
| **1 (solo)** | Viable for specific tools (AI/API hackathons) | Viable for simple games (PICO-8, text-based) |
| **2** | Good for paired programming | Good for programmer + artist |
| **3** | Great — frontend + backend + design | Great — programmer + artist + audio |
| **4** | Full coverage — adds DevOps or PM role | Full coverage — adds designer or second programmer |
| **5+** | Coordination overhead grows | Hard to keep everyone busy |

> **Rule:** 3-4 people is the sweet spot. Smaller teams communicate faster. Larger teams have too much overhead for the time limit.

## Roles by Event Type

### Hackathon Roles

| Role | Responsibility | Ideal For |
|------|---------------|-----------|
| **Frontend** | UI, UX, components, API integration | Web/mobile developers |
| **Backend** | API, database, business logic, auth | Backend/API developers |
| **Designer** | Mockups, branding, pitch deck, user flow | Product designers |
| **DevOps** | Deployment, CI/CD, domain, hosting | Infrastructure engineers |
| **Pitch Lead** | Presentation, demo, narrative | Anyone good at storytelling |

> **Tip:** If you're a team of 3, cover frontend + backend + design. If someone has bandwidth, they also handle DevOps and the pitch.

### Game Jam Roles

| Role | Responsibility | Ideal For |
|------|---------------|-----------|
| **Programmer** | Core mechanics, systems, physics | Game developers |
| **Artist** | Sprites, UI, animations, VFX | 2D/3D artists |
| **Audio** | Music, sound effects, voice | Musicians, sound designers |
| **Designer** | Levels, game feel, balance, mechanics | Game designers |
| **Producer** | Scope, timeline, coordination | Organized generalists |

## Remote Team Coordination

| Challenge | Solution |
|-----------|----------|
| Not in the same room | Voice chat (Discord), shared screen (VS Code Live Share) |
| Different time zones | Async-first, define core overlap hours |
| No whiteboard | Miro / Excalidraw for quick diagrams |
| Version control conflicts | Git — commit early, commit often, small PRs |
| Unclear who's doing what | Shared task board (GitHub Projects, Notion) |

### Remote Team Communication Rules

1. **Stay in voice chat the whole time** — even when heads-down. It keeps the energy.
2. **Screen share freely** — show what you're working on. It sparks ideas and catches problems.
3. **Announce breaks** — "AFK 10 min" so people aren't waiting on you.
4. **Blockers go in chat** — immediate visibility. Someone might have the answer.

## Common Mistakes

| Mistake | Problem | Solution |
|---------|---------|----------|
| Uneven skill coverage | Two frontends, no backend | Align skills before committing |
| No role clarity | People step on each other's work | Assign clear ownership |
| Too many people | Coordination eats build time | 3-4 max, know each other's strengths |
| Solo when you're inexperienced | Burnout, project stalls | Join a team at least once first |
| Not meeting before the event | First hour wasted on intros | Quick pre-event call to align |
