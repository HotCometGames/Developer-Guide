# Developer Wisdom Troubleshooting

> Common traps, burnout prevention, and time management for engineers.

---

## Common Traps

| Trap | What It Looks Like | How to Escape |
|------|--------------------|---------------|
| Gold plating | Adding polish past the point of diminishing returns | Ship it. The next iteration can improve it. |
| Resume-driven development | Choosing tech because it looks good on paper | Pick the tool that solves the problem best |
| Not reading error messages | Jumping to fix without understanding the error | Read the full error and stack trace first |
| Copy-pasting from AI/Stack Overflow | Code works, you don't know why | Understand the code before committing it |
| Ignoring failing tests | Test suite becomes noise | Fix or delete the test immediately |
| "I'll fix it later" | Tech debt compounds | File a ticket, schedule it, or fix it now |

## Burnout Prevention

### Signals

| Signal | What It Means |
|--------|---------------|
| Dreading opening your editor | You need a break or a change |
| Everything annoys you | Mental exhaustion |
| Can't focus for 30 minutes | Cognitive overload |
| Coding feels like a chore | Passion project time |
| Physical symptoms (headaches, insomnia) | Serious — take action |

### Actions

| Action | Why |
|--------|-----|
| Set hard boundaries | Stop at the same time daily |
| Take real breaks | Walk away from the keyboard |
| Timebox side projects | Passion projects should energize, not drain |
| Talk to your manager | They can't help if they don't know |
| Take vacation days | They exist for exactly this reason |

## Time Management

### The Eisenhower Matrix

```
                    Urgent              Not Urgent
Important     Do first (crisis)     Schedule (strategy)
Not Important Delegate (busywork)   Eliminate (distraction)
```

### Timeboxing

Set a fixed amount of time for a task and stop when time's up:

| Task | Without Timebox | With Timebox |
|------|----------------|--------------|
| Research a library | "I'll learn all of it" | "I have 30 minutes to evaluate it" |
| Debug an issue | "I'll stay until it's fixed" | "I'll debug for 45 minutes, then ask for help" |
| Write a design doc | "It needs to be perfect" | "I'll draft it in 2 hours and get feedback" |

### Dealing with Interruptions

| Technique | How |
|-----------|-----|
| Deep work blocks | 2-hour no-interruption window (Slack DND, closed door) |
| Context switching cost | 15+ minutes to regain flow after interruption |
| Batch notifications | Check Slack/email 3x/day, not continuously |
| "Let me get back to you" | Acknowledge, note, respond later |

## Asking for Help

| Instead of | Do |
|------------|----|
| Stuck for 2 hours silently | "I'm stuck on X. I tried A, B, C — what am I missing?" |
| Vague question | Share: goal, what you tried, error messages, what you expected |
| DMing the most senior person | Check docs, check existing issues, then ask the team channel |
| "Can you fix this?" | "Can you point me in the right direction to fix this?" |

## Best Practices to Stay Effective

- **One thing at a time** — multitasking reduces quality on everything
- **Write things down** — todo lists, notes, decisions. Your brain is for thinking, not remembering.
- **Review your week** — 15 minutes on Friday: what worked? What didn't? What to change?
- **Say no more often** — every yes is a no to something else
- **Protect your learning time** — 10% of your week for learning keeps skills from stagnating
